## 1. 왜 하는가 — 두 개념

### 1-1. 데이터 계약 (data contract)

실습 1의 **데이터카드**는 사람이 읽는 설명서입니다. 「출석률은 0~1」이라고 적어 두어도, 다음 달 받은 파일에 `1.3` 이 들어 있으면 아무도 모릅니다.
**데이터 계약**은 같은 약속을 **기계가 매번 대어 보게** 코드로 적은 것입니다.

> 비유 — 택배 검수대. 「상자 크기는 이만큼, 무게는 몇 kg 이하, 송장 번호는 겹치지 않음」을 벽에 써 붙이는 것이 데이터카드, 컨베이어 위에서 자동으로 재고 어기면 멈추는 저울이 데이터 계약입니다.

이 실습의 계약은 칸마다 다섯 가지를 적습니다.

| 약속 | 뜻 | 예 |
|---|---|---|
| `kind` | 자료형 | `"str"` · `"int"` · `"float"` |
| `min` · `max` | 값의 범위 | 비율은 0~1, 횟수는 0 이상 |
| `allowed` | 들어올 수 있는 값의 목록 | 있다/없다는 `[0, 1]` |
| `nullable` | 비어 있어도 되는가 (기본 아니오) | 빈 값을 실습 1에서 채웠다면 v2 에는 빈 값이 없어야 함 |
| `unique` | 겹치면 안 되는가 | `trainee_id` |

계약은 **종료코드**로 답합니다. 어기면 0 이 아닌 값으로 끝나므로, 학습 스크립트 앞이나 자동 점검(CI)에 걸어 두면 잘못된 자료가 들어온 날 학습이 시작되지 않습니다.

### 1-2. 누수 (data leakage)

**누수**는 「예측하는 시점에는 알 수 없는 값」이 학습 자료에 섞여 들어간 것입니다. 모델은 그 칸으로 답을 거의 맞히지만, 실제로 예측해야 하는 날에는 그 칸이 비어 있습니다.

> 비유 — 시험지에 정답이 비치는 종이. 연습 시험에서는 만점이지만 실제 시험지는 다른 종이입니다.

누수를 가르는 질문은 하나입니다 — **「예측하려는 그 시점에 이 값을 알 수 있는가」**. 이 과정의 예측 시점은 「입소 4주 차, 이 사람이 중도에 그만둘지」입니다.

## 4. 단계

명령은 모두 **`lab1_data_version` 폴더**에서 시작합니다. 윈도우 명령 프롬프트에서도 `/` 를 그대로 써도 됩니다.

1. **(1분) 지금 상태** — 2개 통과 · 6개 실패가 나오면 정상입니다.
   ```bash
   python 심화/checks/check-contract.py
   ```
2. **(7분) `contract.py` 의 TODO 1 · TODO 2**
   - TODO 1 — `CONTRACT` 에 나머지 일곱 칸을 적습니다. 칸 이름과 뜻은 `공용데이터/README.md` 의 「열」 표에 있습니다.
     비율은 0~1, 횟수는 0 이상, 있다/없다는 0·1 입니다.
   - TODO 2 — `violations()` 안에 세 검사를 채웁니다. **빈 값은 건너뛰고**(`s.dropna()`) 봅니다.
     `min`/`max` 를 벗어난 건수 · `allowed` 밖의 건수 · `unique` 인데 겹친 건수를 문장으로 `out` 에 넣습니다.
3. **(2분) 자기 v1·v2 에 대어 보기** — v1 은 어기고(종료코드 1), v2 는 지켜야(종료코드 0) 합니다.
   ```bash
   cd 심화/starter
   python contract.py ../../시작코드/data/v1/trainees.csv
   python contract.py ../../시작코드/data/v2/trainees.csv
   cd ../..
   ```
4. **(5분) 누수 가려내기**
   - `starter/leakage.md` 의 표에 칸마다 「언제 생기는 값인가」를 먼저 적습니다. **숫자를 보기 전에** 적으십시오.
   - `starter/leakage_auc.py` 의 `SAFE` 에 넣어도 되는 칸만 남기고 돌립니다.
     ```bash
     cd 심화/starter
     python leakage_auc.py
     cd ../..
     ```
   - 찍힌 AUC 세 줄을 `leakage.md` 에 옮겨 적고, 마지막 한 문장을 씁니다.
5. **(1분) 다시 점검** — 8개 전부 통과하면 끝입니다.

## 5. 점검 8개가 보는 것

| 번호 | 보는 것 | 어떻게 재나 |
|---|---|---|
| K1 | 계약에 아홉 칸이 다 있다 | `CONTRACT` 의 열쇠 |
| K2 | v1 에서 빈 값과 겹친 번호를 둘 다 찾는다 | 실습 1의 v1 에 대어 봄 |
| K3 | v2 는 계약을 지킨다 (위반 0) | 실습 1의 v2 에 대어 봄 — 계약이 너무 좁으면 여기서 걸림 |
| K4 | 범위 밖 출석률 · 라벨 2 · 음수 횟수를 셋 다 잡는다 | 점검기가 일부러 망가뜨린 자료 |
| K5 | 계약에 없는 칸이 끼어 오면 알린다 | `memo` 칸을 붙인 자료 |
| K6 | 어기면 종료코드가 0 이 아니다 | `python contract.py v1` 을 실제로 돌림 |
| K7 | 넣어도 되는 칸에서 누수 칸 둘을 뺐다 | `leakage_auc.py` 의 `SAFE` |
| K8 | `leakage.md` 에 AUC 셋을 옮겨 적었다 | 표의 빈칸 |

v1·v2 는 `시작코드/data` 에 있는 **자기 것**을 먼저 씁니다. 없으면 실습 1을 먼저 끝내십시오.

## 6. 결과를 읽는 법

- AUC 는 「위험한 사람을 위험하지 않은 사람보다 높게 줄 세우는 정도」입니다. 0.5 는 동전 던지기, 1.0 은 완벽입니다.
- 칸 셋을 다 넣었을 때 AUC 가 **0.99 를 넘으면**, 모델이 좋아진 것이 아니라 **답을 베낀 것**입니다. 현업 자료에서 이 정도 숫자가 나오면 축하보다 의심이 먼저입니다.
- 두 누수 칸 중 하나는 이름만 봐도 수상하고, 하나는 **덜 눈에 띕니다**. 「끝까지 다닌 사람만 할 수 있는 일」은 무엇인지 생각해 보십시오.

## 7. 막혔을 때

| 증상 | 이렇게 |
|---|---|
| K2·K3 이 「data/v1·v2 가 없습니다」 | 실습 1을 먼저 끝내 `시작코드/data/v1`·`v2` 를 만드십시오 |
| K3 실패 — v2 가 어긴다 | 계약이 너무 좁습니다. 실제 값의 범위를 `df.describe()` 로 보십시오 |
| K4 실패 | 범위·허용값 검사가 비어 있습니다. 빈 값은 건너뛰고(`dropna`) 봅니다 |
| K6 실패 | 맨 아래 `sys.exit(1 if found else 0)` 을 지우지 않았는지 보십시오 |
| K7 실패 | 「성적이 좋아졌으니 넣는다」가 아닙니다. **언제 생기는 값인지**를 보십시오 |
| AUC 가 0.99 를 넘는다 | 그 숫자가 이 실습의 재료입니다 |
| `FileNotFoundError: ...trainees_2025_extra.csv` | `leakage_auc.py` 를 `심화/starter` 안에서 돌렸는지, `incoming/` 폴더가 그대로 있는지 보십시오 |

## 8. 현업에서는

- 데이터 계약은 직접 짜기도 하고, pandera · Great Expectations 같은 검증 라이브러리로 적기도 합니다. 도구가 달라도 **칸마다 약속을 적고, 어기면 멈춘다**는 생각은 같습니다.
- 누수는 칸 이름만으로 안 잡힙니다. 칸마다 **「이 값은 언제, 누가 적는가」**를 자료를 넘겨준 쪽에 묻는 것이 가장 확실합니다.

## 가져가는 것

그리고 한 문장 — **성능이 갑자기 좋아졌으면 모델보다 칸을 먼저 의심한다.**
