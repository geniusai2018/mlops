# lab4 심화 · 지연을 재고, 묶음으로 받는다

> 실습 4(계약 테스트(교재: 계약 시험) 통과)를 끝낸 뒤에 합니다. **15분 안팎** · 네트워크 불필요 · **선택**(평가하지 않음)
> 고치는 파일은 **실습 4에서 완성한 `시작코드/serve.py`** 입니다. 이 심화에는 따로 `starter/` 가 없습니다.
> 교재 **부록 H-4** 에는 무엇을 하는지와 잰 값이 요약되어 있습니다. 이 문서는 혼자 따라 할 수 있게 개념 · 단계 · 점검 항목을 자세히 적은 것입니다.

## 0. 한눈에

| | |
|---|---|
| 더하는 것 | `POST /predict/batch` — 여러 명을 한 번에 받아 한 번에 답하는 새 창구 |
| 지킬 것 | 실습 4의 바깥 약속(계약 테스트 10개)은 **한 글자도 바꾸지 않는다** |
| 점검 | `심화/checks/check-latency.py` — 6개. 실습 4를 끝낸 코드라면 처음 **1개 통과 · 5개 실패** → 끝 **6개 전부** |
| 가져가는 것 | 「새 요구는 새 창구로, 옛 약속은 그대로」 · 응답 시간은 **p95** 로 말한다 |

## 1. 왜 하는가 — 두 개념

### 1-1. 지연(latency)은 평균이 아니라 p95 로 말한다

API 의 응답 시간은 매번 조금씩 다릅니다. 평균은 몇 번의 아주 느린 응답을 가려 버립니다.
그래서 응답 시간을 작은 것부터 줄 세워 **가운데(p50)**와 **95번째 백분위(p95)** — 「100번 중 95번은 이보다 빠르다」 — 를 봅니다.

> 비유 — 버스 배차. 「평균 10분마다 온다」보다 「20번 중 19번은 15분 안에 온다」가 기다리는 사람에게 쓸모 있는 약속입니다. 사용자가 느끼는 것은 평균이 아니라 **가끔 오래 기다린 기억**입니다.

| 말 | 뜻 |
|---|---|
| p50 (중앙값) | 응답 시간의 가운데 — 보통의 경험 |
| p95 | 느린 쪽 끝 — 운영 약속(SLO)을 걸 때 쓰는 값 |

### 1-2. 묶음 예측(batch)과 상한

담당자가 한 반 30명의 위험도를 한꺼번에 보고 싶어 합니다. 지금은 `/predict` 를 30번 불러야 합니다.
요청 한 번마다 **고정 비용**(주소 찾기 · 입력 검사 · 표 만들기 · 모델 부르기)이 듭니다. 30명을 **표 하나**로 만들어 모델을 **한 번만** 부르면, 한 명당 시간이 크게 줄어듭니다.

다만 **상한**이 없으면, 누군가 10만 건을 한 번에 보내 서버를 멈추게 할 수 있습니다. 그래서 「1건 이상 1000건 이하」를 약속에 적고, 벗어나면 4xx 로 막습니다.

### 1-3. 옛 약속을 건드리지 않는 이유

`/predict` 를 쓰는 화면·프로그램이 이미 있습니다. 그 모양을 바꾸면 그쪽이 모두 깨집니다. 새 요구는 **새 창구**로 내고, 실습 4의 계약 테스트가 그대로 통과하는지로 확인합니다.

## 3. 미션 — 새 창구의 약속

| 약속 | 내용 |
|---|---|
| 주소 | `POST /predict/batch` |
| 받는 것 | `{"items": [훈련생 여섯 항목, …]}` — **1건 이상 1000건 이하** |
| 주는 것 | `{"count": n, "results": [{"risk", "label"}, …], "version": …}` — **보낸 순서대로** |
| 막는 것 | 빈 묶음 · 1001건 이상 · 범위를 벗어난 값 → 4xx |

## 4. 단계

명령은 모두 **`lab4_serve_cicd` 폴더**에서 합니다. 시작하기 전에 `serve.py` 를 복사해 두면(`serve_backup.py`) 좋습니다.

1. **(1분) 지금 상태** — 1개 통과 · 5개 실패입니다.
   ```bash
   python 심화/checks/check-latency.py
   ```
2. **(8분) 묶음 모양과 창구**
   - 한 명의 입력 모양(실습 4의 `Trainee`)을 그대로 쓰고, 묶음 모양을 하나 더 만듭니다.
     ```python
     from pydantic import BaseModel, Field
     class Batch(BaseModel):
         items: list[Trainee] = Field(min_length=1, max_length=1000)
     ```
   - `@app.post("/predict/batch")` 를 새로 엽니다. `items` 를 **표 하나**(`pd.DataFrame`)로 만들고, **지금 모델이 쓰는 칸만**(`USES`) 골라, 모델을 **한 번만** 부릅니다.
   - 한 건씩 답할 때와 같은 선(`THRESHOLD`)으로 `label` 을 정하고, `version` 도 함께 돌려줍니다.
3. **(3분) 상한 확인** — 빈 묶음과 1001건이 4xx 로 막히는지 봅니다. `Field(min_length=1, max_length=1000)` 이면 FastAPI 가 422 로 막아 줍니다.
4. **(3분) 숫자 읽기** — 점검기가 찍어 주는 **한 건씩의 p50 · p95** 와 **묶음의 건당 시간**을 견줍니다.
5. **(확인) 실습 4 계약 테스트**
   ```bash
   python 검증/contract-test.py 시작코드
   ```

## 5. 점검 6개가 보는 것

점검기는 서버를 띄우지 않고 `serve.py` 를 직접 불러(`TestClient`) 잽니다.

| 번호 | 보는 것 |
|---|---|
| L1 | `POST /predict/batch` 가 200 이고, 보낸 200건만큼 답한다 |
| L2 | 묶음의 답에도 모델 버전이 실린다 |
| L3 | 묶음으로 보낸 답이 한 건씩 보낸 답과 같다 |
| L4 | 빈 묶음과 1001건은 막는다 (400 · 413 · 422) |
| L5 | 묶음이 한 건당 시간으로는 더 빠르다 (한 건씩의 p50 보다) |
| L6 | 실습 4의 계약 테스트 10개가 그대로 통과한다 |

`L0  serve.py 를 불러온다` 가 실패로 나오면 `serve.py` 에 문법 오류가 있거나 `mlflow.db` 가 없는 것입니다.

## 6. 결과를 읽는 법

- p95 가 p50 보다 꽤 크다면, 가끔 느린 응답이 섞여 있다는 뜻입니다. 사용자에게 약속할 숫자는 어느 쪽이어야 할까요.
- 묶음의 건당 시간이 한 건씩보다 훨씬 작은 까닭은 모델이 빨라져서가 아니라 **요청 하나마다 드는 고정 비용**을 한 번만 내기 때문입니다.
- 이 숫자는 **노트북 한 대에서 잰 값**입니다. 다른 PC 에서는 다르게 나옵니다. 절대값보다 「몇 배 차이인가」를 보십시오.

## 7. 막혔을 때

| 증상 | 이렇게 |
|---|---|
| L0 실패 | `serve.py` 를 열어 오타를 보고, `시작코드` 에 `mlflow.db` 가 있는지(실습 4의 `준비.py`) 보십시오 |
| L3 실패 — 답이 다르다 | 묶음에서도 **지금 모델이 쓰는 칸만** 골라 넣으셨습니까 (`USES`) |
| L4 실패 | `Field(min_length=1, max_length=1000)` |
| L5 실패 | 묶음 안에서 한 건씩 모델을 부르고 있습니다. 표 하나로 만들어 한 번에 넣으십시오 |
| L6 실패 | 기존 창구를 건드렸습니다. 묶음은 **새 창구**로 냅니다 |
| 결과 순서가 섞인다 | 표를 만든 순서 그대로 `results` 를 만드십시오 — 정렬하지 않습니다 |

## 8. 현업에서는

- 응답 시간 약속(SLO)은 보통 「p95(또는 p99) 몇 ms 이하」로 적습니다. 실습 4의 CI 에 이 숫자를 재는 단계를 더할 수도 있습니다.
- 수천·수만 건을 한꺼번에 처리하는 일은 API 가 아니라 **배치 작업**(밤에 도는 스크립트)으로 빼기도 합니다. 상한은 그 경계를 정하는 숫자이기도 합니다.

## 가져가는 것

**「새 요구는 새 창구로, 옛 약속은 그대로」** — 그리고 응답 시간은 평균이 아니라 **느린 쪽 끝(p95)** 으로 말합니다.
