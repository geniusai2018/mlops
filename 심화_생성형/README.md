## 1. 왜 하는가 — 개념

### 1-1. 바뀌는 것은 「모델 파일」 자리뿐이다

이틀 동안 모델에 한 일은 넷이었습니다 — **기록하고, 비교하고, 게이트(교재: 관문)를 세우고, 되돌린다.**
생성형 AI(LLM)를 쓰는 기능에서는 모델을 우리가 학습하지 않습니다. 대신 우리가 고치는 것은 셋입니다.

| 실습 1~6 (전통 ML) | 생성형 기능 | 왜 |
|---|---|---|
| 학습한 모델 파일 | **지시문(프롬프트)** | 같은 모델도 지시문이 바뀌면 답이 바뀐다 |
| 전처리 · 서빙 코드 | **방어 코드** | 모델 답을 그대로 믿지 않고 검사·보정하는 코드 |
| 검증셋 | **평가 세트** | 정답을 미리 정해 둔 고정 사례들 |
| 데이터 해시(실습 1) | 지시문·코드·평가 세트의 해시(교재: 지문) | 「그때 그 후보」를 다시 가리키려면 |
| `RUN.json` · MLflow 기록(실습 2·3) | 후보마다 MLflow 기록 | 무엇을 무엇으로 평가했는지 |
| 승격 게이트(실습 6) | 평가 게이트 | 미달이면 운영 후보가 되지 않는다 |

### 1-2. 평가 세트와 가짜 모델

LLM 의 답은 부를 때마다 달라질 수 있습니다. 그래서 평가는 **답의 문장**이 아니라 **코드가 계산한 정답**(등급 · 출석률 같은 숫자)과 맞는지로 봅니다.
`evaluation.py` 는 후보 하나를 **표본 20명 × 가짜 모델 다섯**(= 사례 100건)에 돌려 봅니다. 가짜 모델은 실제 LLM 이 저지르는 실수를 흉내 냅니다.

| 가짜 모델 | 흉내 내는 실수 |
|---|---|
| 정직한 | 실수 없음 (기준) |
| 무른 | 등급을 늘 「낮음」이라고 한다 |
| 지어내는 | 출석률을 부풀려 적는다 |
| 시키는대로 | 자료 안에 섞인 지시문을 따른다 (프롬프트 주입) |
| 불안정한 | 가끔 실패하고, 끝내 답하지 않을 때도 있다 |

평가는 두 가지를 셉니다 — **못 넘긴 사례 수**(`failed`)와 **누출 수**(`leaks`, 이름·연락처·사유 원문이 모델에게 넘어간 경우).

### 1-3. 평가 세트에도 버전이 있다

평가 세트를 쉬운 사례로 바꾸면 성적은 오릅니다. 그래서 기록에 **평가 세트의 해시**를 남기고, 승격할 때 **지금의 평가 세트와 같은지** 견줍니다. 다르면 옛 성적으로는 올릴 수 없습니다.

## 2. 폴더 구성

```
심화_생성형/
├─ README.md                  지금 이 문서
├─ evaluation.py              평가 — 완성되어 있음, 고치지 않음
├─ eval_set/                  평가 세트 — 고치지 않음
│   ├─ trainees.json            표본 20명
│   ├─ attendances_sample.json  그들의 출결 기록
│   └─ golden_cases.json        코드가 계산한 정답
├─ candidates/                후보 셋 — 고치지 않음 (비교 대상)
│   ├─ v1_base/                 (교재: v1 기본) 에이전트가 만든 그대로. 정상 응답만 처리한다
│   ├─ v1b_masked/              (교재: v1b 가림) v1 에서 이름·연락처·사유 원문을 안 보내게만 고쳤다
│   └─ v2_guarded/              (교재: v2 방어) 숫자 대조 · 등급 하한 · 실패 시 규칙 응답까지 넣었다
├─ starter/                   ← 여기서 작업
│   └─ llmops.py                TODO 1 · 2 · 3
└─ checks/                    (교재 부록 H 안내문의 「검증/」)
    └─ check-llmops.py        점검 6개 (임시 저장소에서 돌려 봄 — 여러분 기록은 건드리지 않음)
```

`llmops.py` 를 돌리면 `starter/` 안에 `mlflow.db` · `mlruns/` · `current_candidate.json`(지금 운영 후보) · `promotion_log.jsonl`(승격 이력)이 생깁니다.
완성본(`solution/`)과 강사 해설은 실습 뒤에 따로 나눠 드립니다.

## 3. 미션

`starter/llmops.py` 를 채워, 후보 셋을 기록하고 **평가를 통과한 것만** 운영 후보가 되게 하십시오.

| 명령 | 하는 일 |
|---|---|
| `python llmops.py record <후보>` | 후보를 평가하고 MLflow 에 기록 |
| `python llmops.py promote <후보> "<이유>"` | 게이트를 통과하면 운영 후보로 |
| `python llmops.py rollback` | 직전 운영 후보로 되돌림 |
| `python llmops.py status` | 지금 운영 후보 |

## 4. 단계

1. **(2분) 지금 상태** — 1개 통과 · 5개 실패입니다.
   ```bash
   python checks/check-llmops.py          # 심화_생성형 폴더에서
   ```
2. **(6분) TODO 1 — 기록에 다섯** (`record()` 안)
   `mlflow.log_params` 에 다섯을 남깁니다.

   | 열쇠 | 값 | 도구 |
   |---|---|---|
   | `candidate` | 후보 이름 | `name` |
   | `prompt_sha` | 지시문의 해시 | `fingerprint_text(instructions_of(cand))` |
   | `code_sha` | 후보 폴더의 해시 | `fingerprint(cand)` |
   | `evalset_sha` | 평가 세트의 해시 | `evalset_fingerprint()` |
   | `model` | 모델 이름 | `MODEL` |
3. **(6분) TODO 2 — 게이트 셋** (`promote()` 안) — 하나라도 걸리면 `fails` 에 이유를 문장으로 넣습니다.
   - 통과하지 못한 사례가 있다 — `run["metrics.failed"] > 0`
   - 개인정보·사유 원문이 새어 나갔다 — `run["metrics.leaks"] > 0`
   - 평가 세트가 그때와 다르다 — `run["params.evalset_sha"] != evalset_fingerprint()`
4. **(3분) TODO 3 — 이력 한 줄** — `entry` 에 `from`(직전 후보, `before` 에서) · `to` · `why` · `run_id` · `prompt_sha` · `evalset_sha` 를 담습니다.
5. **(3분) 직접 돌려 보기**
   ```bash
   cd starter
   python llmops.py record v1b_masked
   python llmops.py record v2_guarded
   python llmops.py promote v1b_masked "누출을 막았다"
   python llmops.py promote v2_guarded "방어 코드를 더했다"
   python llmops.py status
   cd ..
   ```
   `v1b_masked` 는 거부되고 `v2_guarded` 는 올라가야 합니다. 거부 이유를 읽어 보십시오.

## 5. 점검 6개가 보는 것

| 번호 | 보는 것 |
|---|---|
| G1 | 후보 셋의 기록에 이름 · 지시문 · 코드 · 평가 세트 · 모델이 다 남았다 |
| G2 | 코드가 다른 후보는 해시가 다르고, 평가 세트의 해시는 셋이 같다 |
| G3 | 누출은 막았지만 못 넘긴 사례가 있는 후보(`v1b_masked`)는 거부된다 (종료코드 ≠ 0 · 운영 후보 없음) |
| G4 | 전부 통과한 후보(`v2_guarded`)는 올라간다 |
| G5 | 이력 한 줄에 무엇을 · 왜 · 어느 기록 · 어느 평가 세트인지가 있다 |
| G6 | 평가 세트가 바뀌면 옛 성적으로는 못 올린다 |

- `v2_guarded` 의 방어 코드는 모델의 무엇을 믿고, 무엇을 믿지 않습니까? (`candidates/v2_guarded/risk/service.py` 맨 위 설명)

## 7. 막혔을 때

| 증상 | 이렇게 |
|---|---|
| G1 실패 | `log_params` 의 열쇠 이름이 위 표와 같은지 보십시오 (`prompt_sha` · `code_sha` · `evalset_sha` · `model`) |
| G2 실패 | 지시문은 글의 해시(`fingerprint_text`), 코드는 폴더의 해시(`fingerprint`)입니다 |
| G3 실패 — 올라가 버린다 | 게이트가 비어 있습니다. `fails` 에 이유를 넣으면 거부됩니다 |
| G5 실패 | `entry` 에 여섯 칸을 다 넣었는지 보십시오. `from` 은 `before["candidate"]`(없으면 `None`) |
| G6 실패 | 기록에 남긴 `evalset_sha` 와 **지금** 평가 세트의 해시를 견주십시오 |
| 「평가 기록이 없습니다」 | `promote` 전에 같은 후보를 `record` 하십시오 |
| 경고 글이 잔뜩 뜬다 | 기록은 정상입니다. 검증 스크립트(교재: 점검기) 결과만 보십시오 |

## 8. 진짜 모델로 (선택)

평가는 가짜 모델로 합니다. 진짜 모델의 답을 보고 싶으면 강사가 알려 주는 방법으로 키를 환경 변수에 넣고,
`candidates/v2_guarded` 폴더에서 아래를 돌리십시오. 같은 사람을 세 번 불러 보십시오. 문장은 매번 같습니까. 등급은 같습니까.

```bash
python -c "import json; from risk.llm import OpenAILLM; from risk.service import summarize; t=json.load(open('../../eval_set/trainees.json',encoding='utf-8'))[2]; r=[x for x in json.load(open('../../eval_set/attendances_sample.json',encoding='utf-8')) if x['trainee_id']==3]; print(json.dumps(summarize(t,r,OpenAILLM()),ensure_ascii=False,indent=2))"
```

키는 코드나 파일에 적지 말고 환경 변수로만 넣습니다.

## 9. 현업에서는

- 이 틀을 흔히 **LLMOps** 라고 부릅니다. 이름은 늘어나도(GenAIOps · AgentOps) 하는 일은 같습니다 — 무엇을 바꿨는지 기록하고, 고정된 평가로 견주고, 미달이면 올리지 않고, 되돌릴 자리를 둔다.
- 평가 세트는 운영 중 실제로 틀린 사례를 모아 조금씩 늘립니다. 늘릴 때마다 해시가 바뀌므로, 그때마다 모든 후보를 **다시 평가**해야 공정하게 견줄 수 있습니다.

## 가져가는 것

**평가 세트도 버전(교재: 판)이 있다.** 「지난주보다 좋아졌다」는 말은 같은 평가 세트로 잰 것일 때만 성립합니다.
