## 1. 왜 하는가 — 개념

### 1-1. 학습·서빙 어긋남 (training-serving skew)

모델은 두 자리에서 일합니다. **배우는 자리**(`train.py`)와 **답하는 자리**(실습 4의 API). 두 자리에서 입력을 다르게 손질하면, 배울 때와 다른 모양의 입력을 받게 되어 답이 조용히 틀어집니다. 오류가 나지 않으니 알아채기 어렵습니다.

> 비유 — 요리 학원에서는 계량컵으로 재서 배웠는데, 식당 주방에는 계량컵이 없어 눈대중으로 넣는 것. 레시피(모델)는 같아도 맛(답)이 달라집니다.

지금 `train.py` 는 빈 값을 이렇게 채웁니다.

```python
df[FEATURES] = df[FEATURES].fillna(df[FEATURES].median())   # 나누기 전에, 전체 자료의 중앙값으로
```

여기에 두 가지가 걸립니다.

1. **검증셋이 학습에 비친다** — 중앙값을 전체(학습셋 + 검증셋)에서 구하므로, 검증셋의 값이 채우는 값에 섞여 들어갑니다. 작은 누수입니다.
2. **저장한 모델은 빈 값을 못 받는다** — 채움은 모델 바깥의 코드입니다. 답하는 자리에서 같은 채움을 **또 짜야** 하고, 두 번 짠 코드는 언젠가 어긋납니다.

### 1-2. 해결 — 손질을 모델의 첫 칸으로

scikit-learn 의 `Pipeline` 은 여러 단계를 **하나의 모델**로 묶습니다. 빈 값 채우기(`SimpleImputer`)를 맨 앞 칸에 두면,

- `fit()` 할 때 **학습셋에서만** 중앙값을 배우고,
- 그 값이 모델 파일(`model.joblib`) 안에 함께 저장되며,
- 답하는 자리에서는 빈 값이 든 입력을 그대로 넣어도 같은 방식으로 채워집니다.

### 1-3. 환경 기록

같은 코드라도 scikit-learn · pandas 의 버전(교재: 판)이 다르면 결과가 달라질 수 있습니다. `RUN.json` 에 **파이썬 · scikit-learn · pandas 의 버전**을 `env` 로 남겨 두면, 「그때 그 결과」를 다시 만들 때 무엇을 맞춰야 하는지 압니다.

## 4. 단계

명령은 모두 **`lab2_train_pipeline` 폴더**에서 합니다. 시작하기 전에 `train.py` 를 복사해 두면(`train_backup.py`) 비교하기 좋습니다.

1. **(1분) 지금 상태** — 실습 2를 끝낸 코드라면 2개 통과 · 4개 실패입니다.
   ```bash
   python 심화/checks/check-skew.py
   ```
2. **(8분) 채움을 모델 안으로**
   - `fillna(...)` 줄을 지웁니다(주석으로 남기는 것은 괜찮습니다).
   - `from sklearn.impute import SimpleImputer` 를 더하고, `Pipeline([...])` 의 **첫 칸**에 `("impute", SimpleImputer(strategy="median"))` 을 넣습니다.
   - 모델 파일을 **반드시** 저장합니다 — `joblib.dump(model, OUT / "model.joblib")`
3. **(4분) 환경 기록** — `RUN.json` 에 `env` 를 더합니다.
   ```python
   import platform, sklearn
   "env": {"python": platform.python_version(), "scikit-learn": sklearn.__version__, "pandas": pd.__version__}
   ```
4. **(2분) 점검 둘**
   ```bash
   python 심화/checks/check-skew.py
   python 검증/check-repro.py 시작코드
   ```
5. **(생각) 성능 숫자 비교** — 고치기 전과 뒤의 `RUN.json` 지표를 견줘 보십시오. 달라졌다면 왜일까요.

## 5. 점검 6개가 보는 것

점검기는 여러분의 `train.py` 를 **임시 폴더에 두 번** 돌려 봅니다. 여러분 폴더의 결과물은 건드리지 않습니다.

| 번호 | 보는 것 |
|---|---|
| S1 | 모델 파일(`model.joblib`)이 남는다 |
| S2 | 빈 값이 든 입력(2026-1 기수 원본)을 모델이 **그대로 받아** 답한다 |
| S3 | 나누기 전에 전체 자료로 채우지 않는다 — 코드에 `.fillna(` 가 없다 |
| S4 | 모델 안에 저장된 채움 값이 **학습셋의 중앙값**과 같다 |
| S5 | `RUN.json` 에 `env` (python · scikit-learn · pandas)가 있다 |
| S6 | 그래도 두 번 돌리면 예측이 같다 (실습 2의 약속) |

## 6. 결과를 읽는 법

- 성능 숫자가 **조금 내려갈 수도** 있습니다. 나빠진 것이 아니라, 검증셋을 몰래 엿보던 것을 그만둔 결과입니다. 이전 숫자가 조금 부풀어 있었던 것입니다.
- S2 가 통과했다면, 실습 4의 API 에서 빈 값 채우기 코드를 따로 짤 필요가 없어집니다.
