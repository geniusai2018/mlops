# lab6_rollback · 올릴 것만 올리고, 언제든 돌아온다

> MLOps · 블록 11(운영·회귀 대응) · 제한시간 **30분**
> lab5에서 재학습 모델을 **등록만** 해 두었습니다. 이제 여러분이 **사람** 역할입니다.

## 미션

`promote.py` 와 `rollback.py` 를 고쳐 **게이트(교재: 관문) 있는 승격**과 **한 줄짜리 되돌리기**를 만듭니다.
`검증/check-rollback.py` 11가지를 통과시키십시오.

기억해 둘 문장 하나입니다 — **되돌릴 수 없는 배포는 배포가 아니라 도박입니다.**

## 준비 (한 번만)

```
python 준비.py
```

4개가 등록됩니다.

| 버전 | 무엇 | 2026-2에서 재현율 | 정밀도 |
|---|---|---|---|
| v1 | 옛모델_출석만 | 0.000 | 0.000 |
| v2 | 현행_여섯특징 `@production` | 0.125 | 1.000 |
| v3 | 재학습_새기수만 (lab5 결과) | 0.708 | 0.500 |
| **v4** | **불량_라벨섞임** | 0.542 | 0.302 |

**v4가 이 실습의 함정입니다.** 자료 사고로 정답이 뒤섞인 채 학습된 모델인데,
겉보기에는 v3과 구분이 안 갑니다. **게이트가 없으면 이것이 운영에 올라갑니다.**

## 게이트 기준은 이미 정해져 있습니다

```
재현율 ≥ 0.60      놓치면 안 되는 사람을 놓치지 않는다
정밀도 ≥ 0.40      상담 인력이 감당할 수 있다
```

**lab3 `실험비교.md` 의 「다시 보게 될 조건」에 적어 둔 그대로입니다.**
그때 한가할 때 정해 두었기 때문에, 지금 급할 때 논쟁하지 않습니다.

## 약속한 것

```
python promote.py <버전> [사유]
  기준 미달  → 올리지 않는다 · 종료코드 0 아님 · 별칭 그대로
  기준 통과  → 별칭 이동 + 승격이력.jsonl 한 줄

python rollback.py
  버전을 안 줘도 **직전으로** 돌아간다 + 되돌림도 한 줄
```

## 단계

1. **(3분)** 준비하고 지금 상태를 봅니다. **5개 통과 · 6개 실패**로 시작합니다.
   ```
   python 준비.py
   python ../검증/check-rollback.py .
   ```
   지금 `promote.py` 는 **시키는 대로 그냥 올립니다.** v4를 대면 v4가 올라갑니다.
2. **(10분)** promote TODO 1 — 게이트를 세웁니다. 미달이면 **종료코드 0이 아니게.**
3. **(5분)** promote TODO 2·3 — **옮기기 전에** 현재 버전을 집어 두고, 이력에 한 줄.
4. **(8분)** rollback TODO 1·2 — 버전을 안 줘도 직전으로. 되돌림도 한 줄.
5. **(4분)** 점검. 마지막 항목(B9)은 **API를 고치지 않았는데 바뀌었는지**를 봅니다.
6. **(3분)** **화면으로 확인합니다.**
   ```
   python ../화면/화면.py
   ```
   → 브라우저에서 「새 기수형 훈련생★」을 고른 뒤 **v4 올려 보기 → v3 올려 보기 → 직전으로 되돌리기**.
   v4가 막히고, v3로 답이 **0.23 → 0.85**로 바뀌고, 되돌리면 **0.23**으로 돌아오면 됩니다. 아래 기록에 세 줄이 쌓입니다.
   버튼은 **여러분의** `promote.py` · `rollback.py` 를 그대로 돌립니다 — 게이트가 없으면 v4가 그냥 올라가는 것도 그대로 보입니다.
   처음부터 다시 하려면 화면 창을 끄고(Ctrl+C) 아래 세 줄 — `준비.py` 만 다시 돌리면 v5~v8 로 **또 등록**됩니다.
   ```
   rmdir /s /q mlruns
   del mlflow.db 승격이력.jsonl
   python 준비.py
   ```

## 왜 되돌리기가 한 줄이어야 하나

사고가 난 순간 사람은 세 가지를 동시에 합니다 — 원인을 찾고, 보고하고, 막습니다.
이때 **「어느 버전으로 돌아가야 하지」를 찾기 시작하면** 그 5분이 30분이 됩니다.

되돌리기에서 중요한 것은 빠르기가 아니라 **망설이지 않음**입니다.
돌아갈 자리가 이미 적혀 있으면 판단할 것이 없습니다.

## 고치지 않는 것

`공용/serve.py` 는 **lab4 완성본 그대로입니다. 손대지 마십시오.**
승격도 되돌리기도 **이 파일을 한 글자도 고치지 않고** 됩니다.
그것이 lab4에서 버전 번호를 지운 값입니다.

## 심화 (먼저 끝난 분)

`심화/README.md` — 올리기 전에 옆에 세워 본다 — 도전자 모델의 답을 기록만 한다(그림자 배포). 15분 안팎이고 검증 스크립트(교재: 점검기)가 따로 있습니다.

## 막혔을 때

| 증상 | 이렇게 |
|---|---|
| B3 실패 | 게이트를 세우셨어도 **종료코드**가 0이면 실패입니다. `return 1` |
| B4 실패 | 게이트 검사를 별칭 이동 **뒤에** 하셨습니다. 순서를 바꾸십시오 |
| B6 실패 | `from` · `to` · `why` 가 한 줄에 같이 있어야 합니다 |
| B7 실패 | 직전 자리는 이력의 마지막 이동 줄의 `from` 입니다 |
| B7 — 이력이 비었다 | `promote.py` 가 기록을 안 남기고 있습니다. 거기부터 |
| B8 실패 | 되돌린 줄의 `action` 이 `"rollback"` 이어야 합니다 |
| 검증 스크립트가 별칭을 움직여 놨다 | 정상입니다. 끝나면 **원래 자리로 돌려놓습니다** |

## 대체 경로 (설치가 막힐 때)

별칭 대신 `운영중.txt` 에 버전 번호 한 줄을 적는 것으로도 **똑같은 이야기**가 됩니다.
게이트 · 이력 · 직전 자리 — 셋이 핵심이고, 도구는 나중에 바꿔 끼웁니다.

## 이 실습에서 가져가는 것

**`승격이력.jsonl` 양식과 「게이트 → 기록 → 되돌릴 자리」라는 세 박자.**
훈련생 팀 프로젝트 발표에서 **「사고 나면 어떻게 하십니까」**를 물어보실 때,
이 세 가지가 있는지로 보시면 됩니다.
