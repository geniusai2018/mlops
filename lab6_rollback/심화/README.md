## 1. 왜 하는가 — 개념

### 1-1. 게이트만으로는 모자란 이유

실습 6의 게이트는 **지난 자료**로 모델을 걸러 냅니다. 그런데 올린 뒤에야 보이는 것이 있습니다 — 지금 들어오는 요청의 모양, 처리 시간, 예상 못 한 입력에서의 오류.
그렇다고 바로 올렸다가 문제가 생기면, 그동안 나간 답은 되돌릴 수 없습니다.

### 1-2. 그림자 배포(shadow deployment · 교재: 섀도 배포)

새 모델(**도전자**, challenger)을 운영 모델(**production**) 옆에 세워, **같은 요청을 둘 다에게** 보냅니다.

- 바깥으로 나가는 답은 **언제나 운영 모델의 것**입니다.
- 도전자의 답은 **기록에만** 남습니다. 사용자는 도전자가 있는지도 모릅니다.
- **도전자가 터져도 운영은 멈추지 않습니다.** 도전자의 오류는 기록하고 삼킵니다.
- `production` 별칭은 움직이지 않습니다. 그림자 배포는 **올리지 않는** 일입니다.

> 비유 — 수습 기자. 수습이 쓴 기사는 신문에 실리지 않고 데스크 서랍에만 들어갑니다. 실린 것은 언제나 선배 기사입니다. 몇 주 동안 두 기사를 견줘 본 뒤에야 수습의 이름으로 싣습니다.

### 1-3. 정답이 늦게 오는 문제

중도탈락은 몇 주 뒤에야 압니다. 그래서 그림자 기간에는 먼저 **두 모델이 얼마나 다르게 답했는지**(일치율)를 보고, 정답이 온 뒤에 **둘의 성적**(재현율 · 정밀도)을 견줍니다. 옆에 세워 둔 기간이 곧 정답을 기다리는 기간입니다.

### 1-4. MLflow 별칭 다시 보기

실습 6에서 `production` 별칭을 옮겨 승격·되돌리기를 했습니다. 여기서는 별칭을 하나 더 씁니다 — `challenger`. 모델 버전은 그대로이고, 이름표만 하나 더 붙이는 것입니다.

## 4. 단계

1. **(1분) 지금 상태** — 1개 통과 · 5개 실패입니다.
   ```bash
   python 심화/checks/check-shadow.py          # lab6_rollback 폴더에서
   ```
   「mlflow.db 가 없습니다」가 나오면 `시작코드` 에서 `python 준비.py` 를 먼저 돌리십시오.
2. **(2분) TODO 1 — `challenger` 별칭**
   받은 버전(명령줄의 첫째 값, `sys.argv[1]`)에 `client.set_registered_model_alias(MODEL_NAME, "challenger", sys.argv[1])` 을 겁니다. `production` 은 건드리지 않습니다.
3. **(7분) TODO 2 — `answer()`**
   운영 모델의 답(`mine`)은 이미 만들어져 있습니다. 같은 입력을 도전자에게도 주고, 두 답을 한 줄로 적습니다.
   ```
   {"production": {version, risk, label}, "challenger": {version, risk, label} 또는 None, "error": 예외 이름 또는 None}
   ```
   도전자를 부르는 줄은 `try` 로 감싸고, 실패하면 `challenger` 를 `None`, `error` 에 예외 이름을 적습니다. 그 줄을 `log.write(json.dumps(…) + "\n")` 로 기록에 남기고, **운영 모델의 답을 돌려줍니다.**
4. **(2분) TODO 3 — 일치율**
   도전자가 답한 줄만 골라, 두 모델의 `label` 이 같았던 비율을 `agreement` 에 넣습니다. 함수 안에 이미 있는 `both`(두 판정의 짝 목록)를 쓰고, 소수 넷째 자리까지 반올림(`round(…, 4)`)합니다.
5. **(3분) 돌려 보고 읽기**
   ```bash
   cd 심화/starter
   python shadow.py 3
   cd ../..
   ```
   `starter/shadow_summary.json` 을 엽니다. 두 모델은 얼마나 다르게 답했습니까. 정답이 온 뒤의 성적은 어떻습니까.
6. **(확인) 도전자가 고장 났을 때** — 환경 변수 `SHADOW_BREAK=1` 을 주면 도전자가 매번 오류를 냅니다. 점검기가 이 상황도 대신 돌려 봅니다(H6).

## 5. 점검 6개가 보는 것

점검기는 `shadow.py` 를 도전자 v3 으로 **두 번** 돌립니다 — 평소대로 한 번, 도전자를 고장 낸 채 한 번.

| 번호 | 보는 것 |
|---|---|
| H1 | `challenger` 별칭이 v3 에 걸렸다 |
| H2 | `production` 별칭은 안 움직였다 |
| H3 | 요청 80건마다 두 모델의 답이 한 줄에 적혔다 |
| H4 | 요약의 일치율이 기록에서 다시 세어도 같다 |
| H5 | 정답이 온 뒤의 성적(재현율 · 정밀도)이 두 모델 다 있다 |
| H6 | 도전자가 터져도 운영 모델은 80건 다 답한다 (종료코드 0 · 도전자 실패 80건 기록) |
